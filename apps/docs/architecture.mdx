Roomote keeps the conversation, execution, and review path connected. This
overview explains what happens after someone asks a Roomote agent to do work,
without requiring you to know the repository's internal service layout.

## From request to result

1. A teammate starts a request from the web dashboard, a communications
   provider, source control, Linear, an automation, or the API.
2. Roomote creates or resumes a session, chooses the model and any authorized
   integrations, and selects an environment when the request needs a workspace.
3. A task runs in an isolated sandbox with the repositories, services, and
   variables defined by that environment.
4. The task records its conversation, terminal output, logs, artifacts, code
   diff, and live preview as it works. The session keeps the explanation and
   reports from delegated tasks together.
5. Roomote returns the result to the originating surface and, for code changes,
   can deliver a branch, pull request, or reviewable diff.

## What operators configure

- **Inference providers** supply the models used for coding, orchestration,
  vision, review, and helper work.
- **Environments** define repositories, services, variables, and the sandbox
  setup a task can use.
- **Communications providers** and source-control providers connect Roomote to
  the places where people start work and review results.
- **Integrations and MCP servers** provide additional authorized context and
  tools without sending credentials to task sandboxes.
- **Automations** start repeatable sessions from schedules, provider events,
  manual actions, or webhooks.

The web dashboard is the main configuration and review surface. Chat, source
control, Linear, the API, and automations are ways to interact with the same
Roomote agents and sessions, not separate products.
