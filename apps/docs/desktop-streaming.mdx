Roomote includes a shared remote desktop for environment-backed tasks. Open the
dedicated **Shared Desktop** tab in the task sidebar to view and control the
sandbox display, type, click, and scroll without leaving
Roomote.

The sandbox-side Rust service captures X11, encodes low-latency H.264 video,
and accepts validated input over an authenticated control connection. Shared Desktop uses the same task-scoped preview security
boundary, but it is separate from [Live Preview](/live-previews) and does not
appear in the Live Preview service selector.

Roomote starts the virtual display (TigerVNC's Xvnc, used purely as an X
server with no VNC listener) and the streaming service. Graphical applications
must open on the sandbox's inherited `DISPLAY`.

## Prerequisites

- an environment-backed task using a worker image that includes Shared Desktop
- a graphical X11 application running in the sandbox when you need more than
  the initially empty desktop

The managed desktop port is reserved and authenticated by Roomote. Do not add a
separate environment port for it or expose port `6080` as unauthenticated.
Port `19222` is reserved the same way: it is the loopback DevTools endpoint of
the shared browser described below, and an environment cannot publish it.

Input control belongs to one viewer at a time. Opening the desktop takes
control, and a newer viewer who opens it supersedes the previous one. When
that happens the panel header shows **Take control**, and clicking it or the
desktop takes control back. The sandbox display resizes to match the panel of
the viewer who holds control, so the desktop fills that panel instead of
being letterboxed and follows it when they resize it; other viewers see the
desktop at that size. If the stream or the control connection drops, the
panel reconnects on its own. `ROOMOTE_DESKTOP_STREAM_WIDTH` and
`ROOMOTE_DESKTOP_STREAM_HEIGHT` set the initial size before a viewer connects.
The default target is 60 fps and 6 Mbps; tune `ROOMOTE_DESKTOP_STREAM_FPS` and
`ROOMOTE_DESKTOP_STREAM_VIDEO_BITRATE_KBPS` for the workload and available CPU.
All viewers share one encoder: the service encodes the screen once and fans
the same stream out to every viewer, so extra viewers cost bandwidth rather
than sandbox CPU. There is no viewer limit by default
(`ROOMOTE_DESKTOP_STREAM_MAX_CLIENTS` can set one). A viewer whose tab stops
reading the stream is dropped rather than allowed to stall the encoder.

The header's pop-out button opens the desktop in its own window and hands
input control to it; the panel can take control back at any time.

## Roomote's browser

When a task has a Shared Desktop, the agent's browser is a Chrome window on
that desktop rather than a hidden one. You watch the agent browse in the
Shared Desktop tab, and you can use the same window yourself: the tabs,
cookies, and logins are shared.

- Sign in to a site, pass a 2FA prompt, or solve a CAPTCHA in the window, and
  the agent continues from that signed-in state. The sandbox is the trust
  boundary: anything you sign in to there is available to the agent, and to
  any code the task runs in its sandbox, for the rest of the task. Sign in
  with the access you would give the task itself.
- The window opens the first time the agent uses its browser and stays open
  for the life of the sandbox. The agent works in its own tab and leaves tabs
  it did not open alone.
- You always win, and there is nothing to press first. Clicking, scrolling,
  or typing takes over: the panel shows **You're driving** and the agent's
  page actions wait. They resume about ten seconds after you stop, or at once
  when you select **Hand back**. The agent can still read the page and take
  screenshots in the meantime. Watching, including moving the pointer over
  the video, does not pause it. `ROOMOTE_DESKTOP_STREAM_HUMAN_IDLE_MS` sets
  the ten-second window.
- Recordings made by the feature demo skill use a separate headless browser so
  they start from a clean state.

Tasks without a Shared Desktop keep using a private headless browser.

## Verify performance

Open **Shared Desktop** and select **Start remote desktop**. The statistics
toggle in the header overlays browser-rendered FPS, bitrate, dropped frames,
distance from the live edge, the remote screen size, time to the first
decoded frame, and the number of input events sent. The service's `/metrics`
endpoint additionally reports encoder FPS, bitrate, and pointer positions for
diagnostics.

For a deterministic transport test without a desktop, start the service with
a synthetic input:

```bash
ROOMOTE_DESKTOP_STREAM_CAPTURE_MODE=test roomote-desktop-stream
```

Performance depends on resolution, scene complexity, sandbox CPU allocation,
encoder availability, and network conditions. The service does not imply a
1080p60 or 1-vCPU guarantee; validate the actual environment before selecting
production defaults.

Copy and paste work across the boundary for text. Paste with your usual
shortcut to send your clipboard into the focused sandbox application, and
copy or cut in the sandbox to bring the selection back to your clipboard. On a
Mac, Command is sent as Control, so Command+C, V, X, A, and Z do what you
expect in the Linux desktop.

The mouse pointer you see is your own browser cursor; the sandbox cursor is
not painted into the video, so pointing feels immediate even though the
picture arrives after the encode and network round trip.

## Limitations

- the clipboard carries text only (up to 128 KiB); images, files, and file
  drag-and-drop are not included
- X11 is supported; Wayland and direct DRM capture are not yet supported
- audio is not streamed; a silent audio track would stall the browser's media
  clock and freeze the picture
- browser playback uses fragmented MP4 over HTTP, not adaptive bitrate or
  WebRTC congestion control
- every viewer sees the same desktop; there is one screen and one pointer
