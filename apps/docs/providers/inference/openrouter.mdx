OpenRouter is a multi-provider inference gateway with a broad model catalog and
provider routing controls. It is Roomote's default inference option because one
connection can cover many recommended models.

## Get an API key

Create a key on the [OpenRouter keys page](https://openrouter.ai/settings/keys).
Add credits or configure the account's billing and set an optional key spending
limit before connecting it to Roomote.

## Configuration

Add **OpenRouter** in **Settings > Models** and paste the key, or configure:

```sh
OPENROUTER_API_KEY=...
```

Models use the `openrouter/<vendor>/<model>` form. Roomote adds its full curated
recommended set and offers balanced and quick-turnaround mapping presets. You
can still disable recommendations or add another OpenRouter model by slug.

## Cost behavior

OpenRouter deducts model and provider-route usage from the account balance. Its
model catalog shows current pricing and any route-specific differences. Roomote
records usage, estimates model cost, and displays the remaining key limit when
OpenRouter returns one. The [OpenRouter activity page](https://openrouter.ai/activity)
and account balance are authoritative.

## Verify setup

1. save `OPENROUTER_API_KEY`
2. confirm the recommended model list appears
3. apply a mapping preset or select a default coding model
4. run a small task and confirm the request appears in OpenRouter activity
5. check that Roomote shows a remaining key limit when the key has one

## Roomote previews inside environment tasks

When an environment task starts another Roomote deployment for development or
smoke tests, do not put an OpenRouter key in the environment definition. The
definition and workspace are readable by the sandbox agent.

Instead, create a separate spend-capped OpenRouter key and set it as
`R_SANDBOX_OPENROUTER_API_KEY` on the parent Roomote deployment. This is a
reserved control-plane variable, so it cannot be added under **Settings >
Environments > Deployment Environment Variables**. Configure it in the hosting
platform's secret manager or process environment and restart the parent API
service.

The target environment can then configure its nested Roomote deployment with
non-secret references only:

```yaml
env:
  OPENAI_COMPATIBLE_BASE_URL: ${ROOMOTE_SANDBOX_OPENROUTER_BASE_URL}
  OPENAI_COMPATIBLE_API_KEY: ${ROOMOTE_CLOUD_TOKEN}
  R_MODEL: openai-compatible/google/gemini-3.8-flash
  R_MODEL_REASONING_EFFORT: low
  R_ORCHESTRATION_MODEL: openai-compatible/google/gemini-3.8-flash
  R_ORCHESTRATION_MODEL_REASONING_EFFORT: low
  R_SMALL_MODEL: openai-compatible/google/gemini-3.8-flash
  R_SMALL_MODEL_REASONING_EFFORT: low
```

Roomote supplies the gateway URL and current run-scoped token while preparing
environment tasks. The nested deployment calls the parent at
`/api/inference/sandbox-openrouter/v1`; the parent injects the capped provider
key only when forwarding to OpenRouter. The raw key never enters the worker or
task sandbox. Environment changes apply to new tasks, so start a new task after
saving this mapping.

From the sandbox, verify the route without printing either credential:

```sh
curl --fail --silent --output /dev/null \
  -H "Authorization: Bearer ${ROOMOTE_CLOUD_TOKEN}" \
  "${ROOMOTE_SANDBOX_OPENROUTER_BASE_URL}/models"
```

The command exits successfully when the parent key and run token are valid. A
missing parent key returns `404`; an invalid or expired run token returns an
authentication error.

## Common issues

- **The key has no usable balance.** Add credits or raise its spending limit.
- **A model has no available route.** Check provider routing, privacy settings,
  and model availability in OpenRouter, or select a fallback model.
- **The credit line is absent.** Roomote only shows it when OpenRouter returns a
  numeric remaining limit; uncapped keys may not display one.
