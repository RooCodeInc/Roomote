Voice turns a Fast Session into a natural, full-duplex spoken conversation.
GPT-Live handles listening, speaking, and interruptions while the actual Fast
Session handles questions and work with its selected model, tools, context, and
durable transcript. You can move between voice and text without switching to a
separate voice-only agent.

## Enabling voice

Voice uses OpenAI GPT-Live-1 and is available on deployments that set
`R_VOICE_OPENAI_API_KEY` to a key from an OpenAI project with GPT-Live access.
Voice is opt-in: the deployment's general `OPENAI_API_KEY` is not used, so
enabling OpenAI for task inference does not turn voice on.

When the voice key is not configured the voice button does not appear. The key
stays on the control plane. The browser sends its WebRTC connection offer to Roomote
and receives only the negotiated session answer; it never receives the API key.

## Using voice

1. Select the voice button in a composer: in an open Session, or on the home
   page and the **New Session** dialog to start a fresh Session by speaking.
2. Grant microphone access when the browser asks. A short rising tone
   confirms the conversation is open; a falling tone marks the end.
3. Speak naturally. GPT-Live delegates requests to the Fast Session, and each
   spoken request is cleaned up (filler words, false starts, and misheard
   terms) by the deployment's helper model before it appears in the transcript
   as if you had typed it. From the home page or dialog, the first thing you
   say starts the Session and opens it already in voice mode, where the answer
   is spoken.
4. GPT-Live speaks verified Fast output as it arrives. Speak at any time to
   interrupt; GPT-Live continues listening while it speaks, and corrections
   are sent back through the same Fast Session.
5. Select the voice button again to return to typing. The button stays
   highlighted while the conversation is active.

Voice input requires a browser with microphone and WebRTC support, which
includes current Chrome, Edge, Safari, and Firefox.

## How work is handled

GPT-Live is the conversation layer, not a second task agent. Requests that need
an answer, reasoning, or an action go through the same Fast reply path as typed
messages. That preserves the Session's selected model, tools, permissions, and
transcript. Fast output is cleaned for speech before it is returned to
GPT-Live, so code blocks and raw URLs are not read character-by-character.

GPT-Live is told which repositories, environments, and integrations the Fast
Session can reach, so naming one of them is treated as a request to delegate
rather than something to ask about. The same names guide transcript cleanup,
so a misheard repository name is corrected to the real one.

Brief greetings and clarifying questions can stay in the live conversation and
do not start duplicate Fast work. Ending voice stops the microphone; Fast work
already started remains visible in the Session and follows the normal Session
lifecycle.
